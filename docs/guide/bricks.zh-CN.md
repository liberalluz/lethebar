# 八块积木

[English](bricks.md) · 简体中文

一个包不描述一款游戏。它声明数据文件，每个文件打开引擎的一小部分。一共八块。
没有第九块：一个包想要第九种规则，是在要一个新的引擎能力，不是一个更聪明的
数据文件。

| 玩家体验到什么 | 哪一块积木 |
| --- | --- |
| 会涨会跌、跌到下限就停的数字 | 状态账本 |
| 一个选择让两个数字变不同的量 | 结算规则 + 动作菜单 |
| 十二回合后结束的一局 | 阶段机 |
| 拿到剑之后才出现的选项 | 池 + 检查 |
| 记得谁站在哪里的世界 | 关系 |
| 不是回合、而是冷却这样的限制 | 时钟 |

## 表格

每一行都写明打开这块积木的数据文件，以及读它的引擎文件。表由源码生成，所以
一个移动或消失的读取文件，会先让生成器失败，而不是去误导读者。

| 积木 | 由谁打开 | 由谁读 | 它管什么 |
| --- | --- | --- | --- |
| 1. 状态账本 | `data/ledger.json` | `app/core/ledger.gd` | 一局要保留的资源，每个都有初值、下限和上限 |
| 2. 结算规则 | `data/rules.json` | `app/core/mechanics.gd` | 当状态是这样时，把那个状态改这么多 |
| 3. 动作菜单 | `data/actions.json` | `app/core/menu.gd` | 玩家能做什么、花什么、改什么、多久一次 |
| 4. 阶段机 | `data/phases.json` | `app/core/phases.gd` | 一局有多少回合、经过哪些段位、怎么结束 |
| 5. 检查 | `data/checks.json` | `app/core/checks.gd` | 对状态的一个命名判断，选择或卡牌可以问它 |
| 6. 池 | `data/pools.json` | `app/core/pools.gd` | 一组不重复抽取的物品，或作为手牌发出 |
| 7. 关系 | `data/relations.json` | `app/core/relations.gd` | 谁和谁站在哪边，立场一变会带动什么 |
| 8. 时钟 | `manifest.json` 的 `clock` | `app/core/session.gd` | 什么时候过一回合：每个选择、每个节点，或每 n 个 |

## 一块积木怎么打开

靠声明那个文件。一个有 `data/ledger.json` 和 `data/actions.json` 的包，就有账本和
菜单；两个都没有的包，仍然能装、能玩一个线性故事，因为这两块是一局唯一坚持要的。

省略一个文件不是错误。声明坏了才是：校验器会读 manifest 隐含的每个数据文件，
当其中一个点名了不存在的东西时，拒绝安装。这种形状的三个例子：

- 一个动作花 `gold`，而 `data/ledger.json` 从没声明 `gold` —— `V-16`
- 一条规则把 `standing` 设成 `allied`，而 `data/relations.json` 从没声明
  `allied` 这个状态 —— `V-25`
- 一个动作从 `relics` 抽，而 `data/pools.json` 从没声明那个池 —— `V-26`

完整清单，以及每个码对应的那句话，在[错误页](errors.zh-CN.md)。

## 积木故意不做什么

没有表达式语言。一个条件，要么是资源和数字比较，要么是某个关系成立，要么是
抽到了某件物品；更复杂的，写成几条依次触发的规则。也没有运行时脚本：一个需要
代码的包，是在要 `scripted@1`，引擎不提供，今天的答案是不行。

两个后果：数字是浮点，所以成本 `0.5` 合法；规则按 `data/rules.json` 里出现的
顺序执行，所以后面的规则看得到前面写下的东西。

## 一个块一个名字

块的文件按块命名：`data/ledger.json`、`data/relations.json`、`data/hand.json`。v0.7.5 之前的包用 `state.json`、`factions.json`、`cards.json`；引擎只认块名（ADR-0018）。

## 数据文件里的 id

你在数据文件里写的每个 id——动作、资源、池、关系实体——都满足 `^[a-z][a-z0-9_]*$`：小写字母和数字，用下划线连接，以字母开头。连字符不在这个语法里。

| | |
| --- | --- |
| 可以 | `send_apan_herb`、`stone`、`trust_apan` |
| 不行 | `send-apan-herb`、`2stone`、`trust.apan` |

包 id 是唯一的例外：它允许连字符（`^[a-z0-9-]+$`），因为它是 URL 的一段和存档键，不是数据 id。

这条规则不是装饰。动作 id 会复用在翻译文件的 `action.<id>`、存档的 `used` 表、`disable.json`，还会显示在一局里。玩家有存档之后再改就是一次数据迁移，所以第一次就写下划线形式；语法不对时 `V-16` 在安装时拒绝整个包。

## 比一局更长的记忆

如果你的包需要在两局之间记住东西——商店的存货、玩家选过的名字、只跑一次的标记——在 manifest 里声明它，并声明 `persist@1`：

```json
{
  "capabilities": ["text@1", "persist@1"],
  "persist": {"overseer": "", "rerolls": 0}
}
```

效果用 `persist.` 前缀写，规则用同样的路径读：

```json
{"effects": [{"persist.rerolls": {"add": 1}}]}
{"when": {"key": "persist.rerolls", "op": "gte", "value": 3}, "set": {"flagged": 1}}
```

这张表属于 bundle，不属于一局。它存在存档之外，所以重放旧档看到的是当前记忆，不是那一局的记忆——记忆是玩家的，存档是一局的。键是小写 id，值是标量或标量数组；最多 32 个键、4 KiB。层的表按它的目标 bundle 声明。表太大、类型不对、或没声明能力就带表，`V-47` 会拒绝。
