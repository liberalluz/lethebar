# STP — 测试计划（v0.0.0）

[English](STP.md) · 简体中文

## 范围

覆盖 `SRS.md`（v0.0.0）的三十五条 P1 需求，对照 `SDD.md` 的设计。不覆盖插件市场、
插件编辑器、3D、联机、账号、云存档，也不覆盖原生 iOS 构建；这些都不在 v0.0.0
范围内，因此本文件按设计不给用例。

## 策略

三层，从最便宜的往上：

1. **规则层** —— 不经渲染，通过无窗口入口执行协议与包校验。多数用例在这一层。
2. **集成层** —— 包导入 → 校验 → 安装 → 会话，在引擎内运行但不显示窗口。
3. **浏览器层** —— 手工驱动导出的构建，在真实浏览器里跑，因为「能在浏览器里跑」
   无法在引擎内部证明。

确定性与离线行为各有专门用例，因为它们是结构性主张：它们失败就是架构主张失败，
不只是某个功能失败。

## 环境

| 环境 | 是什么 | 用来跑 |
|---|---|---|
| E1 | Godot 4 无头模式，Linux/Windows 桌面 | 规则层与集成层用例 |
| E2 | Chrome/Edge（最新，桌面） | 浏览器层用例、性能、离线 |
| E3 | iOS Safari（最新） | 只读冒烟、离线刷新 |
| E4 | Node（不经引擎） | JSON 层夹具检查（manifest、存档载荷形状） |

## 入口判据

- `SRS.md` 与 `SDD.md` 已评审并提交（`BL-1` 候选）。
- 插件规范 1.0.0 已发布在 `SDD.md` §3–§5，且在本轮测试期间冻结。
- 至少一个合法包夹具，每个校验码至少一个非法夹具。
- 无窗口入口已存在（见 R-01）。

## 出口判据

- 下列每条 `TC-*` 都已执行并记录通过或失败，附证据。
- 没有未关闭的阻断级或严重级缺陷。
- 每条 P1 需求要么由通过的用例覆盖，要么有显式记录的缺口。
- 离线用例（TC-OFF-*）在 E2 与 E3 上都通过，不能只在 E2 通过。

## 测试计划的风险

| ID | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R-01 | Godot 无头模式跑测试在本项目未验证 | 规则层自动化第一周可能不存在 | 第一批用一个平凡断言验证它；退路是用 Node 夹具骨架 + 手工跑引擎，并记为覆盖度下降 |
| R-02 | 离线刷新依赖 service worker 行为，Chromium 与 Safari 不同 | 离线主张可能只在一个引擎成立 | TC-OFF-* 在 E2 与 E3 都跑；只有 Safari 失败算缺陷，不算「已知限制」 |
| R-03 | 首次进入计时（TC-PERF-001、TC-UX-001）靠人测，数字会飘 | 数字噪声大 | 固定设备档与网络（冷缓存），采三次取中位数 |
| R-04 | 种子恒定时确定性用例可能偶然通过 | 假信心 | TC-DET-001 用两个不同种子，并断言输出不同 |

## 缺口

v0.0.0 没有缺口。`SRS.md` §5 的 `TBD-001`…`TBD-003` 是规范缺口，不是测试缺口：
它们改变存档位数量与交付哪些插件，不改变产品能否被验证。
