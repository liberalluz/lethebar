# STD — 测试设计（v0.0.0）

[English](STD.md) · 简体中文

`STP.md` 中每条用例的正文。每条用例说明运行前必须成立什么、按顺序做什么、以及
判定通过或失败的观察。需要夹具的用例按用途命名夹具，不写文件路径，这样夹具改名
不会让用例失效。

## 用例

### `TC-PLAT-001`

- 覆盖：`REQ-001`
- 前置：E2 浏览器干净配置；导出的构建复制到静态目录并以普通 HTTP 提供；网络可用。
- 步骤：
  1. 打开提供的 URL。
  2. 观察首屏。
  3. 不安装任何东西，直接操作第一个控件。
- 出口：入口屏渲染并列出两个内置插件，没有账号提示，首屏可见后一秒内第一个控件
  有响应。

### `TC-OFF-001`

- 覆盖：`REQ-002`
- 前置：TC-PLAT-001 通过；该配置已在线加载过一次，缓存已建立。
- 步骤：
  1. 在浏览器开发者工具中关闭网络。
  2. 刷新页面。
  3. 从内置插件开一局。
  4. 读取整个刷新与会话过程中的网络面板。
- 出口：入口屏离线可渲染，会话能开始，刷新后网络面板中失败请求为零。

### `TC-FMT-001`

- 覆盖：`REQ-021`
- 前置：无头运行；由同一模板生成的夹具清单（`fmt-bundle`、`fmt-no-layer`、
  `fmt-bad-layer`、`fmt-needs`、`fmt-layer`、`fmt-range`、`fmt-ok`、`fmt-legacy`）；
  除步骤明确先装的那个之外，没有已安装的夹具。
- 步骤：
  1. 装 `fmt-bundle`（格式 `2.0.0`、`kind: bundle`、无依赖）：装得上，玩法与从前一致。
  2. 装 `fmt-no-layer`（`kind: layer` 却没有 `layer`）与 `fmt-bad-layer`
     （`layer: weather`）：都被 `V-23` 拒绝。
  3. 装 `fmt-needs`，它唯一的依赖既没装也不是内置包：被 `V-24` 拒绝。
  4. 先装 `fmt-layer`（`1.0.0`、`kind: layer`、`layer: mod`），再装 `fmt-range`
     （要求 `>=2.0.0 <3.0.0`）：被 `V-24` 拒绝，且消息同时点名 `fmt-layer` 与它已装的版本。
  5. 装 `fmt-ok`，要求 `fmt-layer` 在 `>=1.0.0 <2.0.0`：装得上。
  6. 装 `fmt-legacy`（`specVersion: 1.0.0`）：装得上，且警告列表恰好一条 `W-01`。
- 出口：步骤 1–6 全过；解析不到依赖的 `2.0.0` 包永远到不了游戏画面。

### `TC-LEDGER-001`

- Covers: `REQ-022`
- 前置：无头运行；四个由同一模板生成的夹具包：`ledger-basic`（资源 `power`
  `init 3`、`min 0`、`max 5`；唯一选项的效果加 10）、`ledger-undeclared`（同样的
  账本，一条规则读 `gold`）、`ledger-ordered`（`power` 与 `standing`，一条规则读
  `power` 写 `standing`；选项把 `power` 置 0），以及一个可用的存档位。
- 步骤：
  1. 安装 `ledger-basic` 并打开首场景：会话状态里 `power` 为 3，即声明的 `init`。
  2. 选唯一选项（效果加 10）：`power` 读到 5，即声明的 `max`，而不是 13，也不是
     该选项被拒。
  3. 安装 `ledger-undeclared`：被 `V-14` 拒绝，消息点名 `gold`。
  4. 安装 `ledger-ordered`，打开首场景并做出选择：同一步里 `power` 变 0、`standing`
     变 0，因为规则在效果之后运行。
  5. 在该局打开存档位并保存；读回载荷并恢复：恢复后的状态里 `power` 为 0、
     `standing` 为 0。
- 出口：步骤 1–5 通过；没有数值离开声明的边界，也没有规则在点名账本未声明的资源
  时还能安装成功。

### `TC-TURN-001`

- Covers: `REQ-023`
- 前置：无头运行；夹具 `turn-menu`（账本 `grain` 10、`pop` 0、`prestige` 4；动作
  `recruit` 花费 20 粮并要求 20，`drill` 加 1 人口；阶段机带段位与一条
  `pop >= 3` 的失败；一个名为 `battle` 的判定）与夹具 `turn-run`（粮 25；动作
  `spend` 带 `per_run: 1`；阶段机带两个段位、无失败条件）。
- 步骤：
  1. 安装 `turn-menu` 并读菜单：`recruit` 被列为不可用，原因点名 `grain`。
  2. 点 `recruit`：什么都没变，因为不可用的动作不写值。
  3. 连点两次 `drill`：第二次结束运行，因为 `pop` 到达失败阈值，界面显示原因。
  4. 安装 `turn-run`，点 `spend`：一步之内粮减 20、人口加 1，回合读到 2。
  5. 再点 `spend`：`per_run` 上限拒绝，两个数值都保持原样。
  6. 在两个同种子的会话上跑 `battle`：都记下 `roll`、`bonus`、`total`、
     `target`、`passed`，且两次掷骰相同。
- 出口：步骤 1–6 通过；不可用的动作从不改状态，上限按运行计数，同种子重复同一掷骰。

### `TC-POOL-001`

- Covers: `REQ-024`
- 前置：无头运行；夹具 `pool-draw`（一个三条目、抽一条且不替换的池子，一个两条目、
  抽两条且可替换的池子）、`pool-too-big`（一条目的池子抽两条且不替换）、
  `pool-dupes`（同一条目列两次）。

  3. 从可替换的池子抽两次：它仍是两条。
  4. 存档、读回并恢复：少了条目的池子仍少一条。
  5. 安装 `pool-too-big`：`V-19` 拒绝，消息说明不 `replace` 时抽超容量。
  6. 安装 `pool-dupes`：因重复条目被 `V-19` 拒绝。
- 出口：步骤 1–6 通过；抽取不被重载重掷，同种子复现同一抽取。

### `TC-CLOCK-001`

- Covers: `REQ-025`
- 前置：带时钟积木的引擎构建，以及四个夹具：`clock-turn`（声明 `per: turn`，
  一条规则读 `tick` 并写 `grown`）、`clock-node`（声明 `per: node`）、
  `clock-unread`（声明了时钟却没有规则读它）、`clock-write`（规则写 `tick`）。
- 步骤：
  1. 安装 `clock-turn` 并开始一局；读 `tick`，连做两次 `wait` 动作，再读 `tick`
     与规则写下的值。
  2. 在同一局里推进一个节点、不做动作，再读 `tick`。
  3. 安装 `clock-node`，开始并推进一个节点。
  4. 把回合那一局存进槽位 1，恢复后读 `tick`。
  5. 依次安装 `clock-unread` 与 `clock-write`。
- 出口：`tick` 从零起，第一次动作后为 1、第二次后为 2；读 `tick` 的规则在数到 2 时写入
  它的值；`turn` 时钟不因单纯的节点推进变化，`node` 时钟每次推进都加一；恢复后的运行报出
