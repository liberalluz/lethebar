# SDD — v0.0.0 插件驱动叙事游戏

[English](SDD.md) · 简体中文

> 本文有一处落点（见 §12）。本文不写测试断言；那些属于 STP/STD。

## 1. 本设计的范围

覆盖：运行时拓扑、仓库布局、插件包格式、加载与校验流水线、协议接口、会话
模型、存档模型、资源与离线策略，以及两个内置插件。

推迟：3D 渲染路径、插件市场与网络分发、iOS 构建、跨 schema 版本的存档迁移。
每项推迟都是显式缺口，不是空头承诺。

## 2. 系统结构

### 2.1 运行时拓扑

```text
静态托管（无应用服务器）
  └─ 应用外壳：html + 引擎代码 + 内置插件包
       └─ 浏览器运行时
            ├─ 规则运行时（协议、会话、机制、存档）
            ├─ 渲染运行时（场景、文本、2D 精灵、音频、输入）
            ├─ 包加载器（内存中解压、校验、安装）
            └─ 持久化（经 JS 桥的 IndexedDB）
```

没有服务端组件。运行时不依赖任何后端；托管只提供静态文件。

### 2.2 仓库目录

| 路径 | 内容 |
|---|---|
| `app/core/` | 引擎：启动、注册表、校验器、会话、机制、存档、警告通道 |
| `app/protocols/` | 每个协议版本一个目录（`linear@1`、`turn_based@1`） |
| `app/render/` | 2D 场景渲染、文本排版、资源绑定、输入映射 |
| `content/builtin/<plugin-id>/` | 两个内置插件包（源码形态） |
| `infra/` | 导出预设、构建与检查脚本 |
| `docs/` | intent、SRS、SDD、ADR、runbook |

### 2.3 组件职责

| 组件 | 负责 | 不得负责 |
|---|---|---|
| `包加载器` | 读字节、解压、校验 manifest、安装注册表 | 解释玩法 |
| `协议注册表` | 把 `protocol@version` 映射到实现、做版本闸门 | 读取插件文件 |
| `会话` | 当前节点、进度状态、效果应用、随机数状态 | 渲染、存储 |
| `存档存储` | 存档位元数据、载荷往返、schema 兼容闸门 | 玩法规则 |
| `渲染运行时` | 把会话状态变成可见场景与输入意图 | 决定下一步发生什么 |
| `警告通道` | 收集非致命降级 | 中止会话 |

依赖方向单向：`渲染 → 会话 → 协议 → 数据`。渲染运行时从不直接调用包加载器。

## 3. 插件包格式

### 3.1 包结构

一个插件是一个 zip 文件：

```text
plugin.zip
├─ manifest.json
├─ data/
│  ├─ nodes.json          分支图：节点、选择、效果
│  └─ mechanics.json      插件提供的声明式规则表
└─ assets/
   ├─ textures/*.png
   ├─ audio/*.ogg
   └─ text/*.json
```

解压在内存中进行，不落盘，因此浏览器与原生构建的行为完全一致。

### 3.2 manifest 字段

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | 字符串，`[a-z0-9-]+` | 插件稳定标识 |
| `version` | `X.Y.Z` | 插件版本 |
| `specVersion` | `X.Y.Z` | 编写时依据的插件规范版本 |
| `engine` | 范围 `>=X.Y.Z <Y.0.0` | 可接受的引擎版本 |
| `name` | 字符串 | 显示名 |
| `protocol` | `linear@1` \| `turn_based@1` | 声明的玩法协议 |
| `capabilities` | 字符串数组 | `render.2d`、`audio`、`text` |
| `mechanics` | 字符串数组 | 插件提供的机制 id |
| `entry` | 字符串 | 起始节点 id |
| `saveSchema` | 整数 | 该插件产出的存档载荷版本 |
| `assets` | `{type,path}` 数组 | 声明的资源清单 |
| `kind` | `bundle` \| `layer` | 格式 `2.0.0` 起必填：可独立玩，还是别的包依赖的一块（ADR-0007） |
| `layer` | `profession` \| `genre` \| `mod` \| `content` \| `meta` \| `assets` | `kind` 为 `layer` 时必填，指明它是七层设计里的哪一层 |
| `requires` | `{id, version}` 数组 | 必须已安装才能玩这个包的依赖；`version` 用与 `engine` 相同的范围语法 |

| `clock` | `{per: turn \| node}` | 可选：哪一种推进算一次计数。`turn` 数动作，`node` 数节点推进。引擎一直在计，这个字段只说明规则能读哪一种 |

按 `1.0.0` 写的包不声明后三个字段，仍可安装（§4.2 `W-01`）。

`kind` 是装配读的身份，不是提示：`Session.create` 在 `kind` 为 `layer` 时按层应用，否则按 bundle 合并。bundle 上的 `target` 是这一局忽略的数据，永远不会把包变成层；没写 `kind` 的 format `1.0.0` 包算 bundle。

### 3.3 数据文件

- `nodes.json`：节点含 `id`、`text`、`assets`、`choices[]`；每个选择含
  `label`、`next`、`effects[]`。
- `ledger.json`：账本。每个资源有 `id`、`init`、`min`、`max`，可带显示用 `label`，
  也可用 `labels` 把数值映射成显示文字（例如 `{"2": "名动诸侯"}`）。值始终是数字，
  标签只是代替数字显示，不改变数字。
- `rules.json`：结算规则，每条 `{when, set}`，按文件顺序在所选项自身的效果之后求值。
  规则读到的是效果刚留下的值，所以同一步里标签能跟上数字。`mechanics.json` 保持同一
  形状，在没有 `rules.json` 时被读取，账本之前写的包因此仍能玩。
- 规则点名资源，而不是自由变量：规则读写的每个键都必须在 `ledger.json` 里声明（`V-14`）。
  没有控制流，除比较与算术外没有表达式语言。

- `actions.json`：菜单。每个动作有 `id`、`label`，可带 `costs`、`requires`、
  `effects` 与 `limit`（`per_turn` 或 `per_run`）。代价与效果先作用在副本上再一起提交，
  被拒的动作什么都不写；`requires` 不满足的动作被列为不可用并给出不满足的条件，而不是
  从菜单里消失。
- `phases.json`：`turns`、`ranks`、`fail`。回合数是唯一的记账——段位从它读出，所以恢复
  的存档显示它那一回合的段位。`fail` 在结算之后求值；第一条命中的结束本次运行，它的
  `reason` 就是告诉玩家的那句话。
- `checks.json`：`{id, when, roll, target, bonus}`。判定用会话随机数掷骰，加上
  `bonus.scale * state[bonus.key]`，与 `target` 比较，并把
  `{roll, bonus, total, target, passed}` 记到 `state.checks.<id>`。

- `pools.json`：`{id, items, draw: {n, replace}}`。一次抽取取走 `n` 条，除非 `replace`
  为真；剩下的部分进存档，重载不能重掷；顺序在第一次抽取时由会话随机数固定，
  而不是在加载时打乱。
- `relations.json`：`thresholds` 与 `entities`，每个势力带一组有方向的 `relations`。
  非负阈值是下限、负阈值是上限；引擎不发明状态名，也不假设关系对称。
### 3.4 资源类型

v0.0.0 注册的类型：`texture`、`audio`、`text`。注册表之外的类型不是错误；
该资源被跳过并上报（§8.2）。

## 4. 加载与校验流水线

### 4.1 状态

```text
idle → chosen(file) → unpacked → validated → installed
                        │            │
                        └─ rejected ─┘   （给出原因，安装注册表不动）
```

### 4.2 校验项

| 代码 | 检查 | 结果 |
|---|---|---|
| `V-01` | zip 可读且包含 `manifest.json` | 拒绝 |
| `V-02` | manifest 每个必填字段存在且类型正确 | 拒绝 |
| `V-03` | `id` 符合模式，且未以不同版本安装过 | 拒绝 |
| `V-04` | `specVersion` 在支持窗口内 | 拒绝 |
| `V-05` | `engine` 范围包含当前引擎版本 | 拒绝 |
| `V-06` | `protocol` 存在于注册表 | 拒绝 |
| `V-07` | bundle 的 `entry` 节点存在于其 `nodes.json`；层不检查 | 拒绝 |
| `V-08` | 声明的每个资源路径都在包内 | 警告，跳过该资源 |
| `V-09` | `saveSchema` 为正整数 | 拒绝 |
| `V-14` | 规则读写的每个资源都在 `ledger.json` 里声明，且账本自身形状正确 | 拒绝 |
| `V-16` | 动作 id 唯一、至少一条效果、上限是引擎会统计的那种；它们触碰的每个资源都已声明 | 拒绝 |
| `V-17` | `turns` 至少为 1，段位在 `1..turns` 内递增，每条失败都带原因与条件 | 拒绝 |
| `V-18` | 骰子至少两面、目标落在骰子范围内；加成要点名资源 | 拒绝 |
| `V-19` | 池子不重复列条目、至少抽一个、不 `replace` 时不抽超过容量 | 拒绝 |
| `V-20` | 关系点到的势力都已声明、阈值都是数字、状态名都来自 `thresholds` | 拒绝 |
| `W-02` | 方向不一致的关系对（报告，不重写） | 警告 |
| `W-03` | format 1.0.0 的包只写能力名、不写主版本（报告，仍然可装） | 警告 |
| `V-23` | `kind`、`layer`、`requires` 符合 §3.2 的形状，且 `2.0.0` 的包必须声明 `kind` | 拒绝 |
| `V-24` | 每条 `requires` 都由已安装或内置的包满足，且版本落在声明范围内 | 拒绝 |
| `W-01` | `specVersion` 低于 `2.0.0`：现在可读，`v0.2.0` 起拒绝 | 警告 |
| `V-21` | `clock.per` 是 `turn` 或 `node`，且声明了时钟的包至少有一条规则的 `when` 读 `tick` | 拒绝 |
| `V-25` | 条件里的关系状态在 `relations.json` 里声明过，或点名的条目存在于某个池子里 | 拒绝 |
| `V-26` | 动作的 `draw.pool` 在 `pools.json` 里声明过 | 拒绝 |
| `V-27` | `capabilities` 的每一条都是引擎已提供的 `name@major` 能力标识（ADR-0008） | 拒绝 |
| `V-28` | 压缩包本身、条目数、每个条目解压后的字节与解压总量都在上限内；由加载器在读取清单之前判定 | 拒绝 |
| `V-29` | 每个条目路径都是相对路径、全小写且落在字符集白名单内 | 拒绝 |
| `V-30` | 声明的图片任一边不超过 4096 px，声音不超过 2 MB 且不超过 60 秒 | 拒绝 |
| `V-31` | 规则里的关系变化点名包裹声明过的实体，并带 `add` 或 `value` 数字 | 拒绝 |
| `V-33` | 装配里点名的包没有安装 |
| `V-34` | 层的目标不在装配内、指向自身、链成环，或同一个包被命名两次。 | fatal |
| `V-35` | 同一次装配里两个层写了同一个目标的同一个字段。 | fatal |
| `V-44` | 层的 `target` 已安装，但它的 `kind` 不是 `bundle`。 | fatal，点名该层与目标 |
| `V-45` | 同一次装配里两个层声明了同一条资产路径。 | fatal，点名两个层与路径 |
| `V-36` | 声明 `cards.hand@1` 的包裹带有 `hand` 与 `deck` 的 `data/hand.json` | 拒绝 |
| `V-37` | 每张牌的 `cost` 与 `effects` 都点名账本声明过的资源 | 拒绝 |
| `V-38` | 牌库里的每个牌 id 都在包裹的 `cards` 表里声明过 | 拒绝 |
| `V-39` | 牌指名了没有任何 texture 资源声明的图标 | 致命，`data/hand.json` |

每次拒绝都给出代码与出错字段；拒绝不会扰动已安装插件及其存档。

### 4.3 安装注册表

已安装插件以 `{id, version, manifest, packageBytes}` 记录在本地存储。包字节
一并保存，因此插件在离线与刷新后仍可启动，无需重新导入。用相同 `id` 导入新
版本会替换该条目，并保留该插件的存档位。

## 5. 协议接口

### 5.1 契约

协议实现针对会话状态提供四个操作：

```text
start(session)          → 首个可渲染状态
advance(session, intent)→ 玩家意图生效后的下一状态
evaluate(session)       → 应用机制规则后的状态
snapshot(session)       → 可写入存档位的序列化载荷
```

协议只读取插件数据与交给它的会话状态；不得读文件、读存储或读时钟。

### 5.2 注册表与版本

v0.0.0 支持：`linear@1`（选择驱动节点推进）、`turn_based@1`（回合结构，逐回合
意图）。注册表在校验期拒绝未知的 `protocol@version`，这正是 `V-06` 的意义。

### 5.3 新增协议

新增协议意味着新增引擎代码。这是「引擎不认识玩法」的既有限制：引擎认识的是
**协议接口**，插件在若干实现中选择。SRS 要求的是两种协议，而不是任意新协议；
第三种协议是产品决策，不是插件。

## 6. 会话模型

### 6.1 形态

会话持有：插件标识、协议实例、当前节点、账本数值、随机数状态、警告列表。会话由
某个插件创建，从不跨插件共享。

账本数值在选项效果之后、结算规则之后都会被夹回声明的 `min`/`max`，因此没有任何
路径——选项效果、规则、恢复的存档——能把数字推出边界。夹取不隐藏任何东西：值只是
停在上限或下限。

一局的结束条件是：落到的节点没有选项，**且**包没有声明阶段机。靠菜单游玩的包一定
声明阶段机，它的入口节点通常根本没有选项——只把「没有选项」当成结束，会在第一次
动作之前就把这一局关掉（`REQ-026`）。声明了阶段机的包改由失败条件或回合上限结束，
两者见 §6.3。

### 6.2 机制

机制是声明式的：插件声明机制 id，并在 `rules.json`（此前是 `mechanics.json`）中
提供规则表；会话在每次节点推进后按文件顺序、在所选项刚应用的效果之上应用匹配规则。
v0.0.0 包含两个机制：力量供给（随选择变化的资源）与进度呈现（场景头部显示的派生值）。

### 6.5 时钟

引擎自己维护一个计数 `tick`，每次运行从零开始。它从不读墙上时钟，也没有任何包能声明、
重置或写入它：规则可以在 `when` 里写 `tick`，而 `set` 里写 `tick` 的规则被 `V-14` 拒绝
（`V-21` 管的是相反的错误——声明了时钟却没人读）。

哪一种推进算一次，由包通过 `clock.per` 选：

- `turn`——一次动作把计数加一，单纯的节点推进不加。
- `node`——每次节点推进都计数，包括运行开始时落到入口节点的那一次。
- 不声明——计数仍随节点推进增长，但没有规则能读它，因为 `V-21` 只在声明了时钟时才要求有人读。

声明了时钟的包，在每次动作之后也会跑一遍规则，而不只是节点推进之后；没有时钟的包保持
旧行为，只在推进后跑。计数随存档写走，恢复的运行从玩家离开时的数继续。

### 6.3 确定性

随机性来自会话种子。种子由插件 id 与显式起始计数导出，从不取墙钟。因此相同
选择序列复现相同状态序列。任何组件都不得为玩法决策读取当前时间。

### 6.4 故障隔离

协议或机制出错会中止该会话，退回插件选择并显示错误。已安装插件与其他插件的
存档不受影响。

## 7. 存档模型

### 7.1 存档位

默认每个插件 3 个存档位，按 1–3 排序，各自显示保存时间元数据与取自会话的一行
预览。存档位以插件 `id` 命名空间隔离，两个插件永不共用。

### 7.2 载荷

```json
{ "schema": 1, "plugin": {"id": "...", "version": "..."},
  "node": "...", "state": {...}, "rng": 123456789, "savedAt": "..." }
```

### 7.3 兼容性

读取时：`schema` 必须等于该插件声明的 `saveSchema`，且插件 id 必须与活动插件
一致。任何不匹配都以同时指出两个值的消息拒绝；不做部分载入，v0.0.0 不做自动
迁移。

### 7.4 存储

存档经 JS 桥存放在 IndexedDB，按插件 id 与存档位索引。写入失败（配额、隐私
模式）时会话继续，由警告通道报告该位未写入；绝不在实际未写入时告诉玩家已保存。

### 7.5 落盘

写入不是在调用返回时就算完成，而是在存储层报告「没有待写内容」时才算完成。`SaveStore`
因此带一个请求和一个探针：`write()` 先请求落盘，再问后端是否还在忙，忙的时候报告
`pending`。壳层每帧读这个标志，只有它变为空闲才说这一档已保存。

浏览器里存储是 `user://`，由引擎映射到 IndexedDB 并按自己的节奏刷盘。导出不向页面
暴露这个刷盘动作，所以壳层等的是一段有界的墙上时间（1.5 秒），而不是去调用它。用时间
而不是帧数：无头浏览器一秒画出的帧远超六十帧，按帧计只会是存储真正需要的窗口的一小段。

安装插件包写的是同一个存储，也过同一道门：`mark_writing()` 让刷新也无法抢在安装之前。

读档重建的会话取界面语言，而不是包裹的默认语言。存档记的是一局，不是一项偏好，所以语言
不进载荷：`resume()` 把它当选项收下，壳层传入当前正在读的语言。没有这个字段的旧存档
照样能读，只是回落到包裹自己的文字。

## 8. 资源策略

### 8.1 解析

会话开始时从内存中的包读取资源，按声明类型绑定到渲染槽位。只解码被引用到的
资源。

### 8.2 降级

缺失或未知资源各产生一条警告，渲染为占位（`text` 类型直接渲染资源路径），
永不中止会话。警告按会话聚合、按需展示，不对每个资源弹一次模态框。

### 8.3 摆放

图片画在正文上方的一条带里。带高取「窗口高度的 30%」与「正文与所有按钮占完
之后的剩余高度」两者的较小值，因此换成两行的正文也不会把控件顶出屏幕。场景
没有声明图片时这条带塌成零高度。立绘资源占据正文旁的固定窄列；版面支持
`portrait`，但目前没有随包发布的插件用到它。音频在读者进入引用它的场景时开始
播放，离开该场景时停止。

### 8.4 可接受的格式

图片为 PNG 或 JPEG，声音为 WAV；引擎只调用这三种解码器。其他格式解码失败，
走 §8.2 的降级路径——占位加一条警告——而不是中止。

## 9. 离线策略

- 应用外壳（html、引擎代码、内置包）在首次加载时由 service worker 缓存。
- 已导入插件以字节形式存于安装注册表，因此离线可用且不需要原始文件。
- 无网络冷启动时提供缓存的外壳与内置插件；运行时任何功能都不访问网络。
- 缓存填充失败是警告而非阻断错误：此时游戏退化为仅在线可用，并只提示一次。

## 11. 首次进入路径

落地页 → 插件列表（内置插件已预装）→ 选中三国 → 入口场景。无账号、无网络、
不出现超过一步的对话框链。路径设计目标是首次接触的玩家无需导入任何东西就能
到达一个场景。

落地页点名每个已装故事，给 `New game`；存在存档时再给 `Continue`，后者跨插件
列出所有非空槽并直接恢复选中那一局。

### 11.1 界面语言

界面字符串是数据，不是渲染代码里的字面量。`app/i18n/` 下的 `en.tsv` 与
`zh_CN.tsv` 存放 `key<TAB>text` 行；渲染层向 `Locale` 助手要一个键的文本，
从不内嵌整句。

解析顺序：先看 `user://locale.txt` 里保存的选择，再看浏览器的
`navigator.language`（`zh*` → `zh-CN`，其余 `en`）。缺键回退英文，再回退键名
本身。落地页提供切换；切换后重绘当前屏并持久化选择。有一条断言要求
`app/render` 里不留中文字面量。

### 11.2 包内语言

插件可以选择携带译文而不是复制整份场景。清单声明 `defaultLocale`、随包携带的
其他 `locales`，以及 `names`（每种语言下的显示名）；`data/i18n/<locale>.json`
把节点 id 映射到 `{text, choices}`。

每个字符串的解析顺序：读者语言的表 → 包内默认文本 → 引擎英文。校验会拒绝
「声明了表却不随包携带」「语言不在 `en`/`zh-CN` 里」「表里漏掉某个场景正文或
某个选项」（`V-22`）——半份翻译比没有更糟。表里没出现的场景与选项沿用包内
原文，因此只有清单未声明的语言才允许只给半份表。

### 11.3 场景画出动作菜单

声明了动作的包是靠场景玩的，不只是靠节点选项。场景为每个声明的动作画一个按钮；
当下用不了的动作仍然可见，但处于禁用状态，原因接在标签后面——看不见够不着什么，
玩家就无从规划。读数里带回合与段位，两者都从会话读，渲染层从不自己算。已经结束
的一局显示阶段机给出的原因，并且不再给任何动作按钮；没有动作的包与本节出现之前
渲染得一模一样。

### 11.4 首次访问说明将要下载什么

载荷约 42 MB，由生成的 service worker 缓存，而不是页面自己缓存。落地页因此
在每个 profile 上只说一次体量，而且是在打开任何场景之前：它要求玩家保持标签页
开着——在 iOS 上切走标签页会暂停传输，浏览器可能把它丢掉。这句话出现之后写进
`user://welcome.txt`，回头的玩家不会再读一遍。

载荷到底有没有落地，由 worker 报告，页面不猜。导出时往 `index.html` 注入一段探针：
它通过 `MessageChannel` 向 worker 询问 `lethebar-cache-state`，并把结果发布为
`window.lethebarCache`（`controlled`、`stored`、`error`、`ready`）。渲染层在落地页读取
这个对象；当 `error` 非空时，它用失败信息替换首访那句话，并带上 Cache API 给出的原因。
写入失败于是会出现在界面里，而不是只出现在没人打开的 console 里。

### 11.5 场景说明这一局现在是什么局势

决定一回合的有三个数，场景一个都没显示。`Session.situation()` 把它们读一次：
`turnsLeft` 来自 `phases.turns` 与当前回合；`leaning` 与 `friction` 来自每个实体
收到的关系之和；`tight` 来自每个资源在其声明区间里还剩的比例。引擎不点名任何
阈值、回合上限或资源：所有数都来自包裹，来源未被声明的小节直接不出现，而不是
填一个零。

场景把这份读数作为读数行的又一段打印出来，走 `ui.turns_left`、`ui.leaning`、
`ui.friction`、`ui.tight`，所以这一行和界面其余部分一样跟随界面语言。

### 11.6 一局游戏是由标签构成的，标签也跟随语言

一局不是一个句子：它是一个动作菜单、一个段位、资源读出来时的那个词，以及一局
结束的原因。翻译表过去对这几样东西一个字都没有描述，于是英文局读完英文场景，
接着就撞上中文按钮。

表增加一个可选的 `strings` 段，键就是被命名的那件事：`action.<id>`、
`rank.<turn>`、`resource.<id>.<value>`（对应一份声明过的标签表）、
`failure.<index>`（对应相位机里声明过的失败的位置）。`Session.localise()` 在拼
视图时查表，所以壳层拿到的仍是普通字符串，渲染层没有改动。表里漏掉的键回退到
包裹自己的文字：英文局里出现中文是缺口检查要报的缺陷，而按钮变空是坏掉的一局。

`V-22` 现在按它能描述的同一批键来量。一个为某语言提供了表的包裹，必须把它声明的
每个动作、段位、带标签的取值和失败都译出来——因为只描述场景却忘了菜单的表，正是
这项检查早就拒绝过的半份翻译。


### 11.7 一局可以用牌来打

声明了手牌的一局像一张桌面：场景显示能打的牌，打不起的牌留在屏上并写明原因，打出一张牌就算走一回合。

`app/core/hand.gd` 读声明——`hand.size`、`hand.draw_per_turn`、`hand.reshuffle`、`cards` 表
与初始 `deck`——并在会话开始时发好开局手牌。一张牌带 `cost` 与 `effects`，形状与规则相同，
所以资源名只在账本里查。出牌会付出代价、按规则同样夹取后生效、弃置、补一张（只有包裹要求时才
把弃牌堆放回），并把回合推进一格；打不起的牌以 `S-08` 拒绝，指出缺的是哪个资源，并留在手上。

三堆属于这一局而不属于视图：`snapshot()` 只在包裹声明了手牌时才带 `hand`、`deck`、`discard`，
`save_store.resume()` 在场景画出之前把它们放回去。牌库引用包裹没声明的牌（`V-38`）、牌引用
账本没声明的资源（`V-37`）、声明 `cards.hand@1` 却没有牌文件（`V-36`），都在安装时拒绝，
场景永远不会从一个坏牌库发牌。

### 11.8 牌可以带一张脸

牌是一个带代价的标签，一手全是标签时读得通，但一眼分不清。牌可以指名包里
声明的图片：

```json
{"id": "heavy", "label": "一记重击", "icon": "assets/card-heavy.png"}
```

`card` 这个槽不画在场景带上：场景带只有一张图和一个立绘，而牌面属于手牌里
标签的旁边。手牌把图片画在按钮左侧、尺寸是 `CARD_ICON_SIZE`，标签仍是按钮
文字。

三件事在安装期就定下，而不是画的时候：

- 牌指名了没有任何 texture 资源声明的图标，安装期拒绝（`V-39`）。悄悄丢掉
  脸的牌和从来没有脸的牌是同一种缺陷，只是更难发现。
- 声明了但字节解不出图的资源，保留标签、留一条点名路径的 `R-01` 警告，一局
  照常继续。
- 没有 `icon` 的牌照旧画，没有图片也没有警告。

`REQ-037` 对应 `Hand.icon_of()`、`Session.hand_view()` 与
`Shell.card_rows()`。

### 11.9 长手牌换行

手牌是一行牌，不是一列。容器向窗口要能放下几个 `CARD_COLUMN_MIN` 宽的格子，
其余的换到下一行，所以八张牌在 600 px 下是三行、在 1200 px 下是一行。发牌的
顺序不变，动作菜单仍然是手牌下方的一列。

三件事在排布手牌时定下，而不是画的时候：

- 列数按窗口实际宽度量出来（`Shell.hand_columns()`），写死常量会表现为「永远不
  重新换行」。
- 与别人共享一行的牌，标签在 `HAND_LABEL_CHARS` 处截断并加省略号；能排成一行
  的手牌保留完整标签。
- 场景带、场景文本与动作区保持原来的宽度。只有手牌不再是「一张一行」。

`REQ-038` 对应 `Shell.hand_columns()`、`Shell.hand_row_count()` 与
`Shell._fill_hand_rows()`。

### 11.11 包裹属于哪个世界

仓库按世界切分（ADR-0010），所以一个世界放得下好几个包。包裹用可选的
`collection: {id, names}` 说明这件事：`id` 是世界的机器名，`names` 把语言映射到
玩家读到的标题。

`manifest_schema.gd` 读这个块（`collection_of`）并检查 id 的字母表
（`is_collection_id`，与包裹 id 同一套）。`package_validator.gd` 用 `V-32` 拒绝
结构不对的块——id 不是 slug、`names` 不是语言到标题的映射、或者标题为空——并在
已装的包用另一种写法描述同一个世界时给出 `W-04`；引擎只留一个世界，标题取 id
排序最前的那个包，于是答案与安装顺序无关。

`app/render/shell.gd` 把已装的包分组到世界（`worlds()`），`start_game()` 只在世界
多于一个时打开世界页，所以只有一个题材的仓库仍然保持今天的点击次数。没有声明
世界的包归入兜底世界，它的标题来自界面（`ui.world_other`）。故事列表遵守选中的
世界，`lethebarState.worlds` 公布 id 与标题，浏览器驱动就能按玩家读到的名字点一个

`Hand.draw_into()` 仍是纯函数：拿到三堆，当牌库抽空且包裹允许重洗时，把弃牌堆
按调用方给的顺序放回牌库。没给顺序时按出牌顺序，这是没有 `reshuffle` 的包裹
永远走不到的分支。

会话会把顺序传进去：`_shuffle_cards()` 是在这一局自己的发生器（`_next_rng()`，
由插件 id 与起始计数播种）上跑一遍 Fisher-Yates。因此同一个种子给出同一个顺序，
另一个种子不会，断言才说得出口。三堆随存档一起走，读档保留它携带的顺序而不是
再洗一次；恢复出来的是被存下的那一局，不是新发的一手牌。

### 11.12 一局由多个包组成

会话可以按一份有序的已装包列表打开。第一个包提供节点、阶段机与入口节点，
其余包只能增加资源、动作、卡牌与池子。`PackageLoader.assemble()` 负责解析
这份列表，点名了却没装的包在这里被拒，半个会话不会走到屏幕上（`V-33`）。

这里只是拼装，还不是合并：两个包都声明的键沿用前一个包的值，并留下一条
点名的 `W-05`。覆盖、追加与禁用随 `layer` 字段到来（`ADR-0013`）。这份列表
随存档保存，所以恢复出来的是同一组包。

## 11.13 层包改动的是它命名的那个包

装配条目可以在 id 之外带一个 `target`（REQ-042）。带了就是层：它不再加一个故事，
而是改它下面那个。语义只有三种，没有第四种：层声明的资源定义整体替换基座的定义
（含上下限，当前值按新上下限夹一次）；新的动作、池子、牌追加在基座条目之后；
`data/disable.json` 里列出的名字从动作、池子、牌与账本里移除。

目标在装配时解析，不写进 manifest，因为 `manifest.layer` 已经表示这个包属于六层中的
哪一层（ADR-0007）。目标不在同一装配里、层指向自身、链回到已经走过的包、同一个包
出现两次，都在开局前以 `V-34` 拒绝。

## 11.14 层包说明它改哪个包

层包在自己的 manifest 里写明目标（REQ-043）。`kind` 是 `layer` 的包必须有
`target`；别的 `kind` 带了 `target` 会被 `V-23` 拒掉，因为包上的目标读起来就是
一个忘了声明自己是层的包。装配条目仍然可以带 `target`；两者不一致时以装配为准，
这样测试者可以让同一个层指向另一个基座，而不必改包。

同一个目标上的两个层按装配顺序解析；第二个层写第一个层写过的字段时，以 `V-35`
拒绝，并点名两个层、字段的种类和 id。这项检查在开局前跑完，所以冲突在装配处报告，
而不是玩到中途才发现。

## 11.15 故事怎么读由包声明

包可以在 manifest 里带一个 `content` 块：故事从哪个视角讲（`first`、`third`、`ensemble`）、读数显示多少（`sparse`、`normal`、`dense`）、登场人物（含 id、名字与可选角色），以及一串带回合标签的弧光。`ContentLayer` 在安装时归一这个块，会话把它带进视图，场景照着显示：ensemble 视图保留角色，dense 读数写出弧光段与起始回合，sparse 读数去掉局势行。`V-40` 拒绝引擎不认识的视角或密度并点名字段与取值；`V-41` 拒绝重复 id 或空名字的登场人物，以及回合不递增或重复的弧光。声明随存档一起走，所以读回来的那一局和存下去的那一局读法一致。

## 11.16 包说明它是给谁玩的

包可以带一个 `meta` 块：一到多种语言的 `pitch`、取自 `kids`/`teens`/`adults` 的 `audience`、以分钟计的 `minutes`，以及可选的 `icon`（必须是 manifest 已经声明的纹理）。`MetaLayer` 负责读这个块；包列表用读者语言的介绍、回退到包默认语言、再回退到它有的那种语言，并附上时长。`V-42` 拒绝引擎不认识的受众、不是正数的时长、没有文字的介绍条目与没有纹理提供的图标，每条消息都点名字段。这个块不会被一局游戏读取，所以声明它不会改动存档。

## 11.17 包以带哈希的发布物旅行

包离开仓库时是两样东西：一个 zip 和一份描述。`infra/tool/release/pack.py` 构建 zip 时给每个条目同一个时间戳、按排好的顺序写入，所以同一个目录构建两次字节完全相同；它写出 `<id>-<version>.json`，里面是 id、版本、字节数、sha256、`specVersion` 与引擎区间，并且能把这两个文件上传到某个 release（默认 dry-run）。

引擎通过 `PackageLoader.import_url(url, expected_sha256, context, fetch)` 安装这样的包。字节由调用方提供，从不在这里开 socket：`PackageLoader` 位于 `res://core`，那里不允许出现网络路径。字节先被哈希、以小写十六进制比较；不一致就以 `V-43` 停止安装，写出 url 与两个哈希；fetch 返回空则是 `V-01`，同样写出 url。一致则交给 `import_bytes`，所以安装期的每一条规则（信封、能力、故事自身的校验）对下载来的包和对导入的包完全一样。

## 11.18 引擎用它自己拥有的包证明自己

四个内置故事是内容，不是契约。所以 `app/tests/run_tests.gd` 在打开一个故事之前先问它有没有被 staged：没有就记一次 skip，并在汇总里计数；有就照旧运行。`TC-NEUTRAL-001` 在套件里现造一个小包——两张牌、一个资源、两个动作、一个回合上限——在它身上走 install、play、save、resume，于是世界仓库把故事搬走之后，引擎自己的证明仍然成立。

四个归档全部移走时套件报 `OK — 394 checks, 12 skipped`；都在时报 `OK — 526 checks, 0 skipped`。把守卫改成恒真再移走归档会得到二十六条失败，这正是守卫的意义。

## 11.20 层只应用六个维度里的三个

层声明六个维度之一，引擎目前应用其中三个：`content` 整块替换基础包的块（§11.15），`mod` 改动基础包声明的数值或代价（§11.13），`assets` 把层里的图片并入 bundle 的查找表。另外三个——`genre`、`meta` 与 `profession`——仍是 pending：包能装、manifest 合法，但这一局不改变。

`ManifestSchema.APPLIED_LAYERS` 是这份清单唯一的落点，`layer_applied()` 是所有读者要问的函数。`PackageLoader.assemble()` 把答案记在条目上（`state` 为 `applied` 或 `pending`），并在层的 `target` 已安装却不是 bundle 时以 `V-44` 拒绝，点名该层与目标。包页把 pending 层显示为一句说明、不给勾：一个勾了也不改变任何东西的层会被写进存档的装配，而下一个引擎版本会让同一份存档变成另一局。

资产按装配顺序并入：`PackageLoader._merge_layer_assets()` 把每个层声明的字节复制进 bundle 的查找表，并记下每个路径归哪个层。两个层声明同一路径时以 `V-45` 拒绝，点名两个层与路径，所以胜出者从不取决于顺序。只有层声明过的图片，场景也能画出来；移除该层后恢复 bundle 自己的图。

## 11.21 包或层可以被移除

包页在每个包、每个层旁边给一个移除控件。第一次按下先问，第二次才移除，因为这个控件就在玩家用来开一局的勾旁边；仍有层的 bundle 会提示先移除层，而不是悄悄替玩家移除。

移除会删掉注册表条目与已存字节（`InstallRegistry.uninstall()` 与 `PackageStore.erase()`），从内置清单与所有已勾选的装配里去掉它，并在被移除的包正是当前打开的那一局时关闭会话。`_saves_index()` 只列已安装的包，所以它的存档位从「继续」里消失；点名已移除层的存档以 `E-02` 被拒，点名该层，载荷保留而不是删除。

移除也是让 `V-03` 不再致命的那一步：旧条目没了，同一个 id 同一个版本就能重新安装，这是除了清站点存储之外唯一的出路。

## 11.22 新版本取代已安装的版本

版本号比已安装版本更高的包会直接覆盖它，并只保留一份被取代的版本（`PackageStore.previous:<id>`）。`V-03` 现在只拒绝更低的版本；消息里同时写出两个版本，并提示移除该包或导入更新的版本。重复导入同一版本是允许的，什么都不会变。

只要还存在上一版，包页就显示「恢复 <版本>」。按一次会用 `allow_downgrade` 重新导入那份字节，所以这次显式回滚不会被 `V-03` 拒绝；被它取代的版本成为新的上一版，于是这个控件可以在两个版本之间来回切换。移除包时上一版也一并删除。

存档完全不受影响：槽位按包与槽号存，载荷里记着它运行时用的版本。升级前存的档，只要它点名的节点 id 还在，就会用新版本打开；改掉或删掉这些节点的升级会让存档读不出来，而 `saveSchema` 仍是单向的，所以回滚并不会让更新的存档变得可读。
