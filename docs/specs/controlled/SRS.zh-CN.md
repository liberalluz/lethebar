# SRS — v0.0.0 插件驱动叙事游戏

[English](SRS.md) · 简体中文

> 第一个可玩版本的软件需求。这是范围，不是设计：本文件说明必须成立什么，
> 不说明怎么实现。所有行都是 P1；P2/P3 项列为不在范围内，不混进 P1。

## 1. 范围

一个浏览器游戏，玩法来自已安装的插件。玩家打开链接、导入插件包、选中它、
按该插件自己的协议玩完一段分支并保存。内置两个插件，先三国、后修仙。

## 2. 需求

| ID | 需求 | 验收 |
|---|---|---|
| `REQ-001` | 游戏从 URL 在受支持的浏览器中运行，无需安装、无需账号。 | 在受支持的浏览器打开该 URL，60 秒内出现首屏；不出现登录提示。 |
| `REQ-002` | 成功加载一次之后，断网状态下仍能打开并游玩。 | 关闭网络后刷新页面，仍能开启新局并读取既有存档，不出现错误页。 |
| `REQ-003` | 一局游戏全程不发出网络请求。 | 完整玩一局期间，浏览器网络面板显示 0 个请求。 |
| `REQ-004` | 插件通过导入玩家选择的文件来安装。 | 在系统文件选择器里选中插件包后，插件出现在列表中且可启动；无需手输文件路径。 |
| `REQ-005` | 非法插件被拒绝，并指出具体未通过的检查项，游戏仍可用。 | 导入缺必填字段、规范版本不受支持或引擎版本不兼容的包时，提示该检查项名称，游戏保持可玩。 |
| `REQ-006` | 可安装多个插件，同一时刻只有一个处于活动状态。 | 装有两个及以上插件时，切换到另一个插件生效，原插件的存档不受影响。 |
| `REQ-007` | 仅按公开规范编写的插件无需改动引擎代码即可运行。 | 只依据规范编写的插件进入其首个场景，期间未改动引擎逻辑、未重新构建引擎规则。 |
| `REQ-008` | 选中插件后从其声明的入口开始分支，展示场景与文本。 | 选中插件后 5 秒内显示入口场景文本与至少一个继续控件。 |
| `REQ-009` | 引擎可运行插件声明的至少两种不同玩法协议，且无需改动引擎。 | 两个声明不同协议的插件都能玩完各自第一段，二者切换不需要改引擎。 |
| `REQ-010` | 插件声明的机制在一局内生效。 | 对声明了力量供给与进度呈现的插件，一局中显示所声明的进度值，并按该插件规则变化。 |
| `REQ-011` | 未知或缺失的资源降级为可见警告，而不是崩溃。 | 加载引用了未知资源类型的插件时，出现指名该资源的警告，会话继续。 |
| `REQ-012` | 每个插件各自维护存档位，默认 3 个，任意存档位可读取。 | 某插件三个存档位填满后，读取 2 号位恢复到 2 号位保存的状态；另一个插件的存档位单独列出。 |
| `REQ-013` | 存档记录 schema 版本，不兼容的存档被拒绝并给出提示。 | 将某存档的 schema 版本改为不受支持的值并读取，出现拒绝提示，不启动会话。 |
| `REQ-014` | 内置三国插件，至少包含一段可玩剧情，并按自己的协议游玩。 | 全新安装后选中三国，玩完第一段并可保存、再从该存档继续。 |
| `REQ-015` | 内置修仙插件，至少包含一段可玩剧情，在三国之后交付。 | 全新安装后选中修仙，玩完第一段并可保存、再从该存档继续。 |
| `REQ-016` | 相同输入序列复现相同结果。 | 从新局开始用同样的选择重放，得到完全相同的场景与数值序列。 |
| `REQ-017` | 陌生玩家 10 分钟内进入可玩的一局；作者本人能连玩三局。 | 无引导测试中，首次接触的玩家在打开链接后 10 分钟内到达第一个场景。 |
| `REQ-018` | 界面使用浏览器请求的语言，且玩家可手动切换。 | 浏览器为英文时界面显示英文控件；浏览器为中文时显示中文控件；落地页上的切换在刷新后仍然生效。 |
| `REQ-019` | 插件声明的图片与声音被画出来、放出来。 | 声明了场景图的插件在正文上方以非零尺寸显示该图；未声明的插件不留空白图片区。 |
| `REQ-020` | 插件可携带多种语言的文本，半份翻译的包会被拒绝。 | 浏览器请求英文时，带英文表的插件显示英文正文；声明了译文表却漏掉某个场景或某个选项的包，安装时被 `V-22` 拒绝。 |
| `REQ-021` | 插件声明自己说的是哪个格式版本、是否需要别的包才可玩。 | 声明 `2.0.0` 且无依赖的包照常安装并可玩；`kind`/`layer`/`requires` 形状不合法的包被 `V-23` 拒绝；依赖缺失或版本不在范围内的包被 `V-24` 拒绝；`1.0.0` 的包仍可安装，并带一条 `W-01` 警告。 |
| `REQ-022` | 插件声明自己的数值及其上下限，推动这些数值的规则在选项自身效果之后运行。 | 已声明的资源从 `init` 值起；会越过 `max` 的效果停在 `max` 而不是拒绝该选择；规则点名未声明的资源被 `V-14` 拒绝；规则读到同一选择刚改过的值时看到的是新值；带 `labels` 的资源在场景里显示标签，而数字不变。 |
| `REQ-023` | 插件可以给玩家一个动作菜单、一个有段位与回合数的运行，以及掷骰判定。 | `requires` 不满足的动作被列为不可用并给出不满足的条件，玩家点也不写任何值；`per_run` 上限拒第二次使用且不改任何数值；动作推进回合、段位随回合变化；失败条件结束本次运行并显示原因；判定用会话随机数掷骰，与目标加声明加成比较，并记下决定它的数字。 |
| `REQ-024` | 包可以从池子里抽取条目，也可以记录它的势力彼此怎么看。 | 一次抽取取走声明的条数，除非池子声明可替换；剩下的部分随存档走，所以重载不能重掷；同一个种子抽出同样的条目、同样的顺序；没有 `replace` 却抽得比池子还多是 `V-19`；关系只按包里写的方向读；`ally` 这类状态名来自包自己的 `thresholds`，指向未声明势力的关系是 `V-20`。 |
| `REQ-025` | 包可以按回合计时，规则可以读到引擎记的数。 | 声明 `clock.per` 为 `turn` 的包，每次动作把计数加一、单纯的节点推进不加；声明为 `node` 的包，每次节点推进都加一；规则在 `when` 里写 `tick` 时，计数到数就触发；计数随存档走，恢复后从原数继续；试图写 `tick` 的规则被 `V-14` 拒绝，声明了时钟却没有规则读它的包被 `V-21` 拒绝。 |
| `REQ-026` | 靠动作游玩的包能在场景里玩，而不只是在断言里。 | 声明了动作的包不会因为入口节点没有选项就算结束；场景为每个动作画一个按钮；当下用不了的动作显示为禁用并写出原因，按下不改变任何值；一次动作推进回合，场景显示回合与段位；因失败条件结束的一局显示原因、不再给动作按钮；没有动作的包与以前渲染一致。 |
| `REQ-027` | 动作可以等一个关系状态或一件已抽取的条目，抽签也可以作为动作本身的一步。 | 动作用 `{"relation": "shu", "state": "ally"}` 声明条件时，只要任一实体对 `shu` 处于该状态就能执行；用 `{"drawn": "cao_cao"}` 声明条件时，该条目被抽到后才能执行；不能执行的动作显示为禁用并写明原因；动作声明 `draw` 时在自身这一步从指定的池子里抽一条，抽到的条目随即解锁等它的动作；已抽条目与关系都随存档保存、恢复后仍在；条件点名包内没声明的状态或条目时安装被 `V-25` 拒绝，从没声明的池子里抽时被 `V-26` 拒绝。 |
| `REQ-028` | 存档在界面说「已保存」之前就已经落盘。 | 玩家按下保存后，存档页先说正在保存，落盘之后才说已保存；在显示「已保存」的那一刻刷新，读回来的是同一段进度；等待是有界的，并且不阻塞界面；后端若报告没有待写内容，则立即算已保存。 |
| `REQ-029` | 插件声明它需要引擎提供哪些能力，并带主版本号。 | `capabilities` 的每一条都是 `name@major` 形式的能力标识，且必须在 `docs/specs/capabilities.md` 里列为已提供；其余一律在安装时拒绝，并在拒绝信息里点出是哪个能力；format 1.0.0 的包若只写名字不写主版本，仍然能装，但带一条警告。 |
| `REQ-030` | 插件受一条公开的安装期上限约束。 | 压缩包本身、条目数、每个条目路径与每个条目解压后的字节都在 `docs/decisions/0009-package-trust.md` 的限额内；图片任一边超过 4096 px、音频超过 2 MB 或 60 秒，都会被按名拒绝；拒绝信息写明测到的值与限额。 |
| `REQ-031` | 首次访问时说明正在下载什么、浏览器是否收下。 | 落地页每个 profile 只说一次下载体量，并要求玩家保持标签页；缓存写入失败时把原因说出来而不是静默丢掉；同一 profile 重载不再重复这句话。 |
| `REQ-032` | 规则可以改变关系，存档保得住这个结果。 | 规则点名一个包裹声明过的实体对，以及 `add` 或 `value` 的变化；阵营表只有会话能写；改过的值经存读档仍在；点名未声明实体或非数字变化的规则在安装期被 `V-31` 拒绝。 |
| `REQ-033` | 场景说明这一局现在是什么局势。 | 视图带上剩余回合、众人最拥护的实体、最敌视的实体、最接近下限的资源；只有来源被声明时才出现对应小节；场景用一行画出来，文字来自语言目录。 |
| `REQ-035` | 英文局在包裹提供文字的地方读到英文。 | 菜单标签、段位名、带标签资源的那个词，以及一局结束的原因，都来自包裹为当前语言提供的表；表里漏掉的键回退到包裹原文，而不是空标签；提供了表的包裹必须译出它声明的每个动作、段位、带标签取值与失败，否则 `V-22` 拒绝安装。 |
| `REQ-034` | 内置三国故事是一局完整的运行，不是草稿。 | 它以二十四回合为预算，跨四个资源，回合推进时显示五个段位，可以三种声明过的方式失败，菜单给出五个动作，规则能移动一条关系；全部是包裹数据，装上它 `app/core` 一行不改。 |
| `REQ-036` | 包裹可以发一手牌并持有牌库。 | 包裹声明手牌、一个小牌库和牌本身；场景显示能打的牌，打不起的牌留在屏上并写明原因；打出一张牌会付出代价、生效、弃置、补一张并把回合推进一格；手牌、牌库与弃牌堆在存档与读档后都还在；牌库引用包裹没声明的牌、牌引用账本没声明的资源、声明了能力却没有牌文件，安装时分别以 `V-38`、`V-37`、`V-36` 拒绝。 |
| `REQ-037` | 牌可以指名包裹声明的图片；手牌把图片画在标签旁边，指名了没人声明过的图片的牌在安装期就被拒绝。 | P1 |
| `REQ-038` | 手牌比窗口宽时换成多行，每一张牌和每一个菜单按钮都留在窗口内。 | P1 |
| `REQ-039` | 牌库按这一局的种子洗牌：同一个种子给出同一个顺序，另一个种子不会，存档保留它携带的顺序。 | P1 |
| `REQ-040` | 包裹可以说出它属于哪个世界：落地页先给世界、再给故事，只有一个世界时跳过那一屏，同一个世界的两种写法仍然共用同一个世界。 | P1 |
| `REQ-041` | 一局可以由不止一个包组成。基础包提供节点、阶段机与入口；其余包只能增加资源、动作、卡牌和池子，视图显示的仍是一局。装配里点名而实际没装的包在开局前被拒，并点名该包（`V-33`）。 |
| `REQ-042` | 层包通过覆盖、追加与禁用改动它所命名的包。 | P1 |
| `REQ-043` | 层包在自己的 manifest 里写明它改哪个包；两个层写同一个字段时以稳定错误码拒绝。 | P1 |
| `REQ-044` | 包声明它的故事怎么读：视角、信息密度、登场人物与弧光，场景照此显示。 |
| `REQ-045` | 包说明它是给谁玩的：一句话介绍、受众、时长与图标，包列表显示介绍与时长。 |


## 3. v0.0.0 不在范围内

- 插件市场、在线下载插件、通过网络更新插件。
- 插件编辑器或任何创作界面。
- 3D 渲染（规范保留字段；只实现一条 2D 路径）。
- 联机、账号、云存档。
- iOS 构建、Windows 构建、安卓。
- 跨 schema 版本的存档自动迁移。
- 美术或音频管线：插件可以随包带自己的图片与声音，但没有内置美术、没有编辑、
  没有素材库，也不导入 PNG、JPEG、WAV 之外的格式。
- 英语与简体中文之外的界面语言，以及从右到左的版面。

## 4. 日期有风险时的砍除顺序

砍范围，不动日期。按此顺序砍：

1. `REQ-015` 修仙内置插件（第二个插件）。
2. `REQ-010` 插件声明的机制（保留协议，去掉进度）。
3. `REQ-016` 内置插件之外的确定性保证。

## 6. 重开条件

出现下列任一情况时，本 SRS 作废、项目退回阶段 0 重开，而不是打补丁：

1. 插件加载与播放无法在两周工作内演示通过。
2. 2026-12-31 仍未达成可玩的 v0.0.0。
3. 产品不再是游戏（例如变成面向作者的创作工具）。
4. 出现平台硬约束（应用商店拒绝引擎导出，或浏览器无法运行渲染运行时）。
