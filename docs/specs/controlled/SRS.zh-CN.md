# SRS — v0.0.0 插件驱动叙事游戏

[English](SRS.md) · 简体中文

> 第一个可玩版本的软件需求。这是范围，不是设计：本文件说明必须成立什么，
> 不说明怎么实现。所有行都是 P1；P2/P3 项列为不在范围内，不混进 P1。

## 1. 范围

一个浏览器游戏，玩法来自已安装的插件。玩家打开链接、导入插件包、选中它、
按该插件自己的协议玩完一段分支并保存。内置两个插件，先三国、后修仙。

## 2. 需求

| ID | 需求 | 验收 |
|---|---|---|
| `REQ-001` | 游戏从 URL 在受支持的浏览器中运行，无需安装、无需账号。 | 在受支持的浏览器打开该 URL，60 秒内出现首屏；不出现登录提示。 |
| `REQ-002` | 成功加载一次之后，断网状态下仍能打开并游玩。 | 关闭网络后刷新页面，仍能开启新局并读取既有存档，不出现错误页。 |
| `REQ-003` | 一局游戏全程不发出网络请求。 | 完整玩一局期间，浏览器网络面板显示 0 个请求。 |
| `REQ-004` | 插件通过导入玩家选择的文件来安装。 | 在系统文件选择器里选中插件包后，插件出现在列表中且可启动；无需手输文件路径。 |
| `REQ-005` | 非法插件被拒绝，并指出具体未通过的检查项，游戏仍可用。 | 导入缺必填字段、规范版本不受支持或引擎版本不兼容的包时，提示该检查项名称，游戏保持可玩。 |
| `REQ-006` | 可安装多个插件，同一时刻只有一个处于活动状态。 | 装有两个及以上插件时，切换到另一个插件生效，原插件的存档不受影响。 |
| `REQ-007` | 仅按公开规范编写的插件无需改动引擎代码即可运行。 | 只依据规范编写的插件进入其首个场景，期间未改动引擎逻辑、未重新构建引擎规则。 |
| `REQ-008` | 选中插件后从其声明的入口开始分支，展示场景与文本。 | 选中插件后 5 秒内显示入口场景文本与至少一个继续控件。 |
| `REQ-009` | 引擎可运行插件声明的至少两种不同玩法协议，且无需改动引擎。 | 两个声明不同协议的插件都能玩完各自第一段，二者切换不需要改引擎。 |
| `REQ-010` | 插件声明的机制在一局内生效。 | 对声明了力量供给与进度呈现的插件，一局中显示所声明的进度值，并按该插件规则变化。 |
| `REQ-011` | 未知或缺失的资源降级为可见警告，而不是崩溃。 | 加载引用了未知资源类型的插件时，出现指名该资源的警告，会话继续。 |
| `REQ-012` | 每个插件各自维护存档位，默认 3 个，任意存档位可读取。 | 某插件三个存档位填满后，读取 2 号位恢复到 2 号位保存的状态；另一个插件的存档位单独列出。 |
| `REQ-013` | 存档记录 schema 版本，不兼容的存档被拒绝并给出提示。 | 将某存档的 schema 版本改为不受支持的值并读取，出现拒绝提示，不启动会话。 |
| `REQ-014` | 内置三国插件，至少包含一段可玩剧情，并按自己的协议游玩。 | 全新安装后选中三国，玩完第一段并可保存、再从该存档继续。 |
| `REQ-015` | 内置修仙插件，至少包含一段可玩剧情，在三国之后交付。 | 全新安装后选中修仙，玩完第一段并可保存、再从该存档继续。 |
| `REQ-016` | 相同输入序列复现相同结果。 | 从新局开始用同样的选择重放，得到完全相同的场景与数值序列。 |
| `REQ-017` | 陌生玩家 10 分钟内进入可玩的一局；作者本人能连玩三局。 | 无引导测试中，首次接触的玩家在打开链接后 10 分钟内到达第一个场景。 |
| `REQ-018` | 界面使用浏览器请求的语言，且玩家可手动切换。 | 浏览器为英文时界面显示英文控件；浏览器为中文时显示中文控件；落地页上的切换在刷新后仍然生效。 |
| `REQ-019` | 插件声明的图片与声音被画出来、放出来。 | 声明了场景图的插件在正文上方以非零尺寸显示该图；未声明的插件不留空白图片区。 |
| `REQ-020` | 插件可携带多种语言的文本，半份翻译的包会被拒绝。 | 浏览器请求英文时，带英文表的插件显示英文正文；声明了译文表却漏掉某个场景或某个选项的包，安装时被 `V-22` 拒绝。 |
| `REQ-021` | 插件声明自己说的是哪个格式版本、是否需要别的包才可玩。 | 声明 `2.0.0` 且无依赖的包照常安装并可玩；`kind`/`layer`/`requires` 形状不合法的包被 `V-23` 拒绝；依赖缺失或版本不在范围内的包被 `V-24` 拒绝；`1.0.0` 的包仍可安装，并带一条 `W-01` 警告。 |
| `REQ-022` | 插件声明自己的数值及其上下限，推动这些数值的规则在选项自身效果之后运行。 | 已声明的资源从 `init` 值起；会越过 `max` 的效果停在 `max` 而不是拒绝该选择；规则点名未声明的资源被 `V-14` 拒绝；规则读到同一选择刚改过的值时看到的是新值；带 `labels` 的资源在场景里显示标签，而数字不变。 |
| `REQ-023` | 插件可以给玩家一个动作菜单、一个有段位与回合数的运行，以及掷骰判定。 | `requires` 不满足的动作被列为不可用并给出不满足的条件，玩家点也不写任何值；`per_run` 上限拒第二次使用且不改任何数值；动作推进回合、段位随回合变化；失败条件结束本次运行并显示原因；判定用会话随机数掷骰，与目标加声明加成比较，并记下决定它的数字。 |

## 3. v0.0.0 不在范围内

- 插件市场、在线下载插件、通过网络更新插件。
- 插件编辑器或任何创作界面。
- 3D 渲染（规范保留字段；只实现一条 2D 路径）。
- 联机、账号、云存档。
- iOS 构建、Windows 构建、安卓。
- 跨 schema 版本的存档自动迁移。
- 美术或音频管线：插件可以随包带自己的图片与声音，但没有内置美术、没有编辑、
  没有素材库，也不导入 PNG、JPEG、WAV 之外的格式。
- 英语与简体中文之外的界面语言，以及从右到左的版面。

## 4. 日期有风险时的砍除顺序

砍范围，不动日期。按此顺序砍：

1. `REQ-015` 修仙内置插件（第二个插件）。
2. `REQ-010` 插件声明的机制（保留协议，去掉进度）。
3. `REQ-016` 内置插件之外的确定性保证。

## 6. 重开条件

出现下列任一情况时，本 SRS 作废、项目退回阶段 0 重开，而不是打补丁：

1. 插件加载与播放无法在两周工作内演示通过。
2. 2026-12-31 仍未达成可玩的 v0.0.0。
3. 产品不再是游戏（例如变成面向作者的创作工具）。
4. 出现平台硬约束（应用商店拒绝引擎导出，或浏览器无法运行渲染运行时）。
